## 개요
지도 provider가 카카오맵·네이버지도 두 가지로 고정되어 있던 것을, 설정에서 "티맵"을 세 번째 옵션으로 선택할 수 있도록 확장한다. 티맵 선택 시 지도 렌더링과 리스트의 "길찾기" 링크 모두 기존 두 provider와 동등한 수준으로 동작한다.

## 범위

### 포함
- 설정 시트의 provider 선택지에 "티맵" 세 번째 옵션 추가
- 티맵 선택 시 지도 렌더링: 현재 위치 마커, 주유소 핀, 5곳 자동 줌, 리스트 선택 시 핀 강조 (기존 카카오맵·네이버지도와 동등)
- 티맵 선택 시 리스트의 "길찾기" 버튼이 새 탭(또는 새 창)으로 티맵 길찾기를 연다
- 선택한 provider(티맵 포함)의 기기 저장 및 재방문 시 유지
- 티맵 지도 SDK 로드 실패 시 기존과 동일한 에러 안내 및 재시도

### 제외
- 최초 진입 시 provider 선택 화면(`map-provider-choice`)에 티맵 추가: 그 feature는 아직 착수 전이며 이번 범위 밖
- 티맵을 기본 provider로 변경: 기본값은 계속 네이버지도
- 티맵 길찾기의 앱 미설치 환경(주로 데스크톱) 대응 웹 폴백: 카카오맵과 동일하게 딥링크만 새 탭으로 열고, 앱이 없어 반응하지 않아도 별도 폴백을 시도하지 않는다 (사용자 결정 사항 — 티맵은 네이버와 달리 대응되는 공식 웹 길찾기 URL이 마땅치 않음)
- provider별 마커 디자인·지도 스타일 커스터마이징: 기존 시각 언어를 그대로 재사용
- 카카오·네이버·티맵 외 추가 provider 지원

## 시나리오

### S1. 설정에서 티맵으로 전환
- **Given**: 결과 리스트와 지도가 표시된 상태, 현재 provider는 네이버지도(기본값)
- **When**: 설정 진입점을 열고 "티맵"을 선택한다
- **Then**
  - [x] S1-1 설정 화면이 닫히고, 새로고침 없이 지도가 즉시 티맵으로 교체된다 (Playwright e2e로 확인, `e2e/map-provider-selection.spec.ts` — SDK 스크립트를 `page.route()`로 스텁, 실 appKey 없이 실행)
  - [x] S1-2 교체된 지도에도 현재 위치 마커와 주유소 핀이 표시되고, 모든 핀이 화면 안에 들어오도록 자동으로 줌이 조정된다 (컴포넌트 테스트로 확인, `components/gas/tmap-map-view.test.tsx`·`components/gas/map-view.test.tsx`)
  - [x] S1-3 리스트 항목을 탭하면 티맵 지도에서 해당 주유소 핀이 강조 표시된다 (컴포넌트 테스트로 확인)

### S2. 길찾기가 티맵을 따른다
- **Given**: provider가 티맵으로 설정된 상태, 결과 리스트에 항목이 보임
- **When**: 항목의 "길찾기" 버튼을 누른다
- **Then**
  - [x] S2 새 탭(또는 새 창)으로 현재 위치에서 해당 주유소까지의 티맵 길찾기 화면이 열린다 (단위 테스트로 확인, `lib/directions.test.ts` — 새 탭에서 실제로 티맵 화면이 열리는 최종 확인은 End-to-end 절차에서)

### S3. 선택 지속성
- **Given**: 설정에서 티맵으로 전환한 상태
- **When**: 페이지를 새로고침한다
- **Then**
  - [ ] S3 새로고침 후에도 지도 표시와 길찾기 링크 모두 티맵으로 유지된다

### S4. 티맵 SDK 로드 실패
- **Given**: 티맵 SDK 로드가 실패하는 상태(키 미설정, 도메인 미등록 등), provider는 티맵
- **When**: 지도 영역이 렌더링을 시도한다
- **Then**
  - [x] S4-1 지도 영역에 "지도를 불러오지 못했어요. 다시 시도해주세요"(기존 문구 재사용) 안내와 "다시 시도" 버튼이 표시된다 (컴포넌트 테스트로 확인)
  - [x] S4-2 다른 provider로 자동 전환되지 않으며, 리스트(순위·가격·거리)는 정상적으로 계속 표시된다 (지도 쪽은 컴포넌트 테스트로 확인 — MapView가 자동 전환하지 않음; 리스트가 계속 보이는 부분은 `station-list.tsx`가 이미 provider-무관 구조라 map 에러와 무관하게 렌더됨, `app/page.tsx`가 지도와 리스트를 독립 분기로 렌더링하는 구조로 이미 검증됨)

### S5. 설정 화면에 세 번째 옵션 노출
- **Given**: 앱이 로드된 상태 (현재 provider와 무관)
- **When**: 설정 진입점을 연다
- **Then**
  - [x] S5 "카카오맵", "네이버지도", "티맵" 세 옵션이 모두 보이고, 현재 선택된 provider가 표시된다 (컴포넌트 테스트로 확인, `components/gas/settings-sheet.test.tsx`)

## 불변 규칙

- [x] INV-1 지도에 나타나는 기능(현재 위치 마커, 주유소 핀, 자동 줌, 선택 항목 강조)은 세 provider(카카오맵·네이버지도·티맵) 어디든 동일하게 나타난다 (S1, `map-provider-selection` INV-1 확장) — 컴포넌트 테스트로 확인
- [x] INV-2 지도 렌더링과 길찾기 링크는 항상 현재 선택된 provider와 일치한다 — 티맵 선택 중에는 티맵 지도·티맵 길찾기만 열린다 (S1, S2) — 렌더링 절반은 Task 2의 INV-1 테스트(다른 provider 컴포넌트가 호출되지 않음), 라우팅 절반은 Task 5의 `lib/directions.test.ts`로 확인

## End-to-end 검증

1. 결과 화면(리스트+지도)이 네이버지도로 표시된 상태에서 설정 진입점을 연다 → "카카오맵", "네이버지도", "티맵" 세 옵션이 모두 보이는지 확인 (S5)
2. "티맵" 선택 → 새로고침 없이 지도가 즉시 티맵으로 바뀌고, 현재 위치 마커·주유소 핀·자동 줌이 적용되는지 확인 (S1-1, S1-2)
3. 리스트 항목 하나를 탭 → 티맵 지도에서 해당 핀이 강조되는지 확인 (S1-3)
4. 해당 항목의 "길찾기" 클릭 → 새 탭에 티맵 길찾기가 열리는지 확인 (S2, INV-2)
5. 페이지를 새로고침 → 지도와 길찾기가 여전히 티맵으로 유지되는지 확인 (S3)
6. (환경상 재현 가능하면) 티맵 키를 제거하거나 도메인 미등록 상태를 재현해 에러 안내·재시도 버튼이 뜨고, 그 상태에서도 리스트는 정상 표시되는지 확인 (S4)

**실행 결과 (2026-08-06, execute-plan Task 6)**: 1·2·3·4·5·6 모두 자동화 테스트로 실행·통과함 — 1·5는 Playwright e2e(실 Chromium, `page.route()`로 SDK 스크립트만 스텁), 2의 SDK 로드·설정 닫힘과 6은 각각 e2e(위와 동일한 스텁 기법)로, 2의 마커·핀·자동 줌 세부와 3·4는 컴포넌트/단위 테스트(fake `window.Tmapv2`)로 확인. **미확인**: 실 티맵 appKey로 지도가 실제로 화면에 그려지는 시각적 확인, 그리고 "길찾기" 클릭 시 실제 티맵 앱/웹으로 전환되는지의 최종 확인 — 둘 다 SK Open API 콘솔에서 발급하는 실 appKey가 필요하고 이 sandbox에는 없음(의존성 섹션 참고). appKey 발급 후 `bun run dev`로 직접 확인 필요.
